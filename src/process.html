Process

Routing runs in this browser. Place search uses keyless Photon and the map uses OpenFreeMap vector tiles from OpenStreetMap data. Your people and settings stay on this device.

Starts matched to nearby stops

Each start place is matched to nearby transit stops within a fixed walking radius. A stop saved from the local list uses the stop itself; an address or map pin uses the closest stops around that point.

Walk tolerance per person

Every person has a walk tolerance from 0 to 60 minutes in 5-minute steps, set on their card with a default of 20 minutes. When a place is within that walking time of a start, its walking time is used for that person instead of a transit time. Changing the tolerance re-groups fair areas from the travel times already computed; it does not change which transit paths exist. Walk tolerance stays per person. Areas are compared by the active metric: travel time in Time mode or fares in Fare mode. The Parameters panel has one global Include average headway checkbox, saved with settings and share links; it controls whether the interchange wait below is charged and shown.

Multi-source Dijkstra

Those nearby stops become the sources of a multi-source Dijkstra search over a local transit graph. Walking links connect the sources, and ride edges follow the scheduled network. Each boarding adds a fixed penalty (one minute on rail, two minutes on bus). When the Include average headway parameter is on, the solver also adds up to half of the day's average time between services, weighted by how long the ride lasts, but only when a ride follows another transit leg: the first boarding assumes the traveller times their departure, so it has no headway wait. With the parameter off, no headway wait is charged anywhere. Every reachable place gets a travel time for each person.

Fair-cell grouping

The map is divided into small cells. Cells are grouped by how different the results are across everyone, then ordered by the active metric so the fairest areas for the active metric appear first. Time mode compares travel time; Fare mode also compares fares. The displayed spread and longest values are whole-minute times. The tolerance control changes this grouping without re-running the whole search.

Route legs

Route legs follow the shapes stored in the transit feed. Walking segments connect a start to a stop, a stop to a ride, and the last ride to the meeting area. Ride segments trace the actual path of the MTR or bus line rather than a straight line between stops. MTR legs use the full line name, such as Tsuen Wan Line, Kwun Tong Line or Tuen Ma Line, instead of a three-letter code. Each ride chip shows the stops as Start → End with a Unicode arrow. Every ride leg includes its fixed boarding penalty; when the headway parameter is on, a leg boarded after another transit leg also carries its interchange wait, shown as a whole-minute note such as Interchange wait 4 min in the leg details and in the route tooltip. The first ride leg has no such note, and no wait note appears when the parameter is off. Every minute value is shown as a whole number.

Fare estimates

Fares are adult Octopus fares looked up from the MTR's published station-pair fare matrix, bundled from MTR open data as a build-time snapshot; Airport Express uses its own published table. Bus and ferry fares come from the Transport Department full-fare snapshot and are shown as exact. Only fares with no snapshot entry use a distance band and are marked ≈. Fares affect the active objective in Fare mode but never which areas are time-feasible.

Data sources

The transit graph comes from a community-maintained Hong Kong GTFS feed. The interest index uses open Hong Kong government data and Overture. Place search uses Photon, and the basemap uses OpenFreeMap vector tiles from OpenStreetMap data.
