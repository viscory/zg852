Process

Routing runs in this browser. Place search uses keyless Photon and the map uses OpenFreeMap vector tiles from OpenStreetMap data. Your people and settings stay on this device.

Starts matched to nearby stops

Each start place is matched to nearby transit stops within a fixed walking radius. A stop saved from the local list uses the stop itself; an address or map pin uses the closest stops around that point.

Walk tolerance per person

Every person has a walk tolerance from 0 to 60 minutes in 5-minute steps, set on their card with a default of 20 minutes. When a place is within that walking time of a start, its walking time is used for that person instead of a transit time. Changing the tolerance re-ranks fair areas from the travel times already computed; it does not change which transit paths exist. Walk tolerance stays per person. The time-versus-fare fairness choice is different: it is one trip setting for everyone in the options panel, not a toggle on each person card.

Multi-source Dijkstra

Those nearby stops become the sources of a multi-source Dijkstra search over a local transit graph. Walking links connect the sources, and ride edges follow the scheduled network. Each boarding adds a fixed penalty (one minute on rail, two minutes on bus). The solver also adds a capped, duration-weighted day-average headway halved, but only when a ride follows another transit leg: the first boarding assumes the traveller times their departure, so it has no headway wait. Every reachable place gets a travel time for each person.

Fair-cell grouping

The map is divided into small cells. Cells are grouped by how different the results are across everyone, then ranked so the fairest, quickest areas appear first. The trip fairness metric decides what is compared: in Time mode the spread and longest values are whole minutes, and in Fare mode they are adult Octopus fare amounts. The tolerance control changes this grouping without re-running the whole search.

Route legs

Route legs follow the shapes stored in the transit feed. Walking segments connect a start to a stop, a stop to a ride, and the last ride to the meeting area. Ride segments trace the actual path of the MTR or bus line rather than a straight line between stops. MTR legs use the full line name, such as Tsuen Wan Line or Kwun Tong Line, instead of a three-letter code. Every ride leg includes its fixed boarding penalty; a leg boarded after another ride also carries its interchange wait, shown as a whole-minute note such as Interchange wait 4 min in the leg details and in the route tooltip. The first ride leg has no such note. Every minute value is shown as a whole number.

Fare estimates

Fares are adult Octopus estimates based on the ride distance and operator fare bands. They are shown for comparison only; check the operator for exact fares. When the trip fairness metric is set to Fare, these estimates also provide the spread and longest values shown with each area.

Data sources

The transit graph comes from a community-maintained Hong Kong GTFS feed. The interest index uses open Hong Kong government data and Overture. Place search uses Photon, and the basemap uses OpenFreeMap vector tiles from OpenStreetMap data.
